VANILLA JAVASCRIPT · THREE RECIPES

One grid.
Three uses.

Monthloom supplies the dates. Your application owns availability, selection, habits, and event records. These fictional examples use February 2024 so their behavior stays reproducible.

Try selecting an available day or toggling a habit. Nothing is saved or sent.

Booking availability

Unavailable weekends are disabled. Selecting a weekday updates app-owned state; this is not a booking service.

const unavailable = new Set([3, 4, 10, 11, 17, 18, 24, 25]);
// In your renderer:
button.disabled = unavailable.has(date.getDate());
// Store the chosen date in your application.

Habit tracker

Toggle any day. Pressed buttons indicate completion; state lives in memory and resets on reload.

const completed = new Set([1, 2, 5, 6, 8]);
// In your click handler:
if (completed.has(day)) completed.delete(day);
else completed.add(day);
button.setAttribute('aria-pressed', String(completed.has(day)));

Event-marked month

Attach your event data to dates. Monthloom does not fetch events, schedule meetings, or expand recurrence rules.

const events = new Map([[7, 'Design review'], [15, 'Community meetup']]);
// Render events.get(date.getDate()) beside the day.

These day-number keys are scoped to this single demo month. For a multi-month app, use full local year-month-day keys.
